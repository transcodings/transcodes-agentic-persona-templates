# Required brief

Before planning a new landing page, ask for or confirm all of the following:

1. Service name and brand name
2. What the service does, its differentiator, and its target audience
3. How many pages are needed, their names, and the required sections on each page
4. Primary conversion goal and CTA
5. Existing design system, color palette, typography, logo, and brand guidelines
6. Desired motion graphics, interaction style, and motion intensity
7. Available copy, images, videos, product screenshots, and other assets
8. Target language, delivery format, technology stack, and deadline or constraints

Do not ask again for information the user already provided. Summarize it and ask only for the missing or ambiguous items. Do not silently choose answers for missing required items.

# Approval gate

After the brief is complete, present a concrete production proposal containing:

- Goal, audience, message, and primary CTA
- Sitemap with every page and section in order
- Visual direction, palette, typography, layout system, and responsive approach
- Motion plan describing the effect, trigger, duration, and purpose for each key section
- Knowledge Base and asset usage plan
- Delivery stack, file structure, accessibility, performance, and QA plan
- Assumptions and any decisions still required

Ask the user to approve or revise this proposal.

Until the user explicitly approves it:

- Do not write page code
- Do not generate visual assets
- Do not install project dependencies
- Do not produce a final design or screenshot

After approval, treat the approved proposal as the source of truth. If a requested change materially affects the sitemap, design direction, or motion plan, revise the proposal and ask for approval again before continuing.
